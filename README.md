# Telegram-бот лид-магнит (подписка на канал → PDF)

Простой production-ready Telegram-бот на **Python 3.12 + aiogram 3.x**.

Флоу: **Start → Подписаться → Проверить подписку → PDF**.

Пользователь приходит по deep link из Instagram:

```
https://t.me/BOT_USERNAME?start=guide
```

Бот просит подписаться на канал, проверяет подписку через Bot API
(`getChatMember`) и после успешной проверки присылает PDF-файл в личный чат.

Без сторонних конструкторов (BotHelp и т.п.) — просто скрипт на aiogram.

## Структура проекта


## Куда положить PDF

Файл инструкции нужно положить по пути, указанному в переменной
`PDF_PATH` (по умолчанию `assets/guide.pdf`), то есть:

```
telegram-lead-magnet-bot/assets/guide.pdf
```

Если файла там не будет — бот всё равно запустится (чтобы не блокировать
работу /start и проверку подписки), но при попытке выдать инструкцию
пользователь получит вежливое сообщение об ошибке, а в лог попадёт понятная
запись с путём к отсутствующему файлу. При старте приложение дополнительно
явно проверяет наличие файла и пишет в лог предупреждение, если его нет.

## Переменные окружения (`.env`)

Скопируй `.env.example` в `.env` и заполни:

| Переменная            | Что это                                                                 | Пример                                |
|------------------------|--------------------------------------------------------------------------|----------------------------------------|
| `TELEGRAM_BOT_TOKEN`   | Токен бота от [@BotFather](https://t.me/BotFather)                       | `123456789:AAExxxxxxxxxxxxxxxxxxxxxxx` |
| `CHANNEL_ID`           | Канал, подписку на который нужно проверять. `@username` или числовой `-100...` | `@my_channel` или `-1001234567890`     |
| `CHANNEL_URL`          | Публичная ссылка на канал (для кнопки "Подписаться")                     | `https://t.me/my_channel`              |
| `PDF_PATH`             | Путь к PDF-файлу инструкции                                              | `assets/guide.pdf`                     |
| `BOT_USERNAME`         | Username бота без `@` (для итоговой ссылки и лога)                       | `my_lead_magnet_bot`                   |

**`.env` никогда не коммитить** — он в `.gitignore`. Полный токен также
никогда не пишется в логи (в логах виден только числовой id бота, а не
секретная часть токена).

`CHANNEL_ID`:
- публичный канал → `@channel_username`;
- приватный канал → числовой id вида `-1001234567890` (его можно узнать,
  например, переслав сообщение из канала боту вроде `@username_to_id_bot`,
  или посмотрев его в `getChat`/логах после первого запуска).

## Обязательное условие: бот должен быть админом канала

`getChatMember` не сработает, если бот не состоит в канале как
администратор. Настрой это один раз:

1. Открой канал в Telegram.
2. **Управление каналом** (Manage Channel).
3. **Администраторы** (Administrators) → **Добавить администратора** (Add Administrator).
4. Выбери своего бота в списке.
5. Подтверди добавление (права на публикацию сообщений боту не нужны —
   достаточно того, что он состоит в канале как админ).

При старте приложение само проверяет права бота (`getChatMember` для
самого бота) и пишет в лог явное предупреждение, если бот не админ —
это не останавливает запуск, но подписка не будет проверяться, пока
права не выданы.

## Локальный запуск (long polling)

```bash
python3.12 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# заполни .env своими значениями

mkdir -p assets
cp /путь/к/твоей/инструкции.pdf assets/guide.pdf

python bot.py
```

При старте бот:
1. проверит токен (`getMe`);
2. проверит канал и права администратора;
3. проверит наличие PDF;
4. выведет в лог готовую ссылку для рекламы:
   `https://t.me/BOT_USERNAME?start=guide`.

Останавливается по `Ctrl+C` — сессия закрывается корректно.

## Docker / production

```bash
docker build -t lead-magnet-bot .
docker run --rm --env-file .env -v $(pwd)/assets:/app/assets lead-magnet-bot
```

Подходит для Railway (worker service), Render (background worker), VPS
или любого always-on хостинга. Эта версия использует **long polling** —
домен и webhook не требуются.

**Важно:** long polling требует, чтобы процесс работал непрерывно.
Не используй хостинг, который "засыпает" фоновые процессы при
отсутствии HTTP-трафика (например, бесплатный web-tier некоторых
платформ, рассчитанный на HTTP-сервисы, а не воркеры) — бот перестанет
отвечать. Нужен именно "worker"/"background service"/VPS-режим,
работающий 24/7.

Процесс корректно завершается по `SIGTERM`/`SIGINT` (aiogram сам
устанавливает обработчики сигналов и закрывает HTTP-сессию бота), так что
`docker stop` останавливает его без обрывов.

## Как это работает

1. **`/start`** (в том числе с `?start=guide`) — только в личных чатах.
   Бот присылает приветствие и клавиатуру из двух кнопок:
   «Подписаться на канал ❤️» (ссылка) и «Проверить подписку ✅» (callback).
2. **Проверить подписку** — бот вызывает `getChatMember(CHANNEL_ID, user_id)`,
   где `user_id` берётся **только** из реального `callback.from_user.id`
   (никогда из текста/данных, присланных пользователем).
   - `creator` / `administrator` / `member` → подписан.
   - `restricted` с `is_member=true` → подписан.
   - `left` / `kicked` / `restricted` с `is_member=false` → не подписан.
3. Если не подписан — сообщение "Я пока не вижу подписку 👀" и те же
   две кнопки.
4. Если подписан — сообщение "Готово ❤️" и следом PDF-документом (с подписью).
5. Повторное нажатие подписанным пользователем — можно повторно выдать
   PDF (это ок для MVP). Быстрые повторные нажатия (несколько раз подряд)
   гасятся встроенным анти-спамом (`throttling.py`, 2 секунды на
   пользователя) — это не требует базы данных.
6. В группах бот не отвечает вообще (фильтр `chat.type == "private"` на
   всех хендлерах) — ни `/start`, ни выдача PDF там не работают.

## Если нужно ограничить выдачу PDF одним разом (будущее развитие)

Сейчас файл можно получить повторно — это специально сделано простым
(MVP без БД). Архитектура готова к расширению: `handlers.py` в одном
месте (`process_check_subscription`) принимает решение "выдавать / не
выдавать" — там же легко добавить проверку в БД вида
`if already_received(user_id): не выдавать` перед отправкой документа,
подключив, например, SQLite/PostgreSQL через отдельный модуль
`storage.py` без изменения остальной логики.


фиктивными значениями — приложение корректно логирует диагностику и
завершается (для токена) или продолжает работать (для канала/PDF) без
необработанных исключений.

> Полноценные сценарии с реальным ботом (реальная подписка/отписка живого
> пользователя в реальном канале, реальный деплой) требуют настоящих
> `TELEGRAM_BOT_TOKEN` и канала — их нет в этой среде разработки. Все 12
> сценариев проверены логически через модульные/интеграционные тесты с
> замоканным Bot API; после того как ты впишешь свои `TELEGRAM_BOT_TOKEN`
> и `CHANNEL_ID` в `.env`, стоит один раз пройти чек-лист руками.

## Безопасность

- Токен только через переменные окружения, никогда в коде.
- Полный токен никогда не пишется в лог (маскируется, виден только id бота).
- `.env` в `.gitignore`.
- `user_id` для проверки подписки берётся исключительно из
  `callback_query.from_user.id` — никогда из `callback_data` или текста.
- Бот не выполняет никаких путей/команд, переданных пользователем;
  `PDF_PATH` задаётся только через окружение сервера.
- Все вызовы Telegram API оборачены в обработку исключений; пользователю
  показываются только общие сообщения, техническая информация — только в лог.
